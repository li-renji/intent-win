# 手机端模型能力实测报告

> 测试时间：2026-10-24 10:05
> 目标模型：`qwen2.5-1.5b-mnn` @ `http://192.168.3.4:9999/v1`（手机本地 MNN 推理）

## 结论速览

| 能力 | 结果 | 说明 |
|---|---|---|
| 接受 `tools` 参数 | ✅ HTTP 200 | 但**只是当普通字段忽略**，不是真正支持 |
| 产生 `tool_calls` | ❌ 从未出现 | 给了完整 schema + `tool_choice:auto`，仍只回纯文本 |
| 纯文本对话 | ✅ 正常 | 流式/非流式均可 |
| 稳定性 | ⚠️ 差 | 手机深度睡眠导致 25~30s 超时，间歇性可达 |

## 关键证据

### 1. 上游接受 tools 参数，但从不生成 tool_calls

带完整 function schema + `tool_choice:"auto"` 请求：

```json
{"model":"qwen2.5-1.5b-mnn","messages":[{"role":"user","content":"帮我看看百度首页"}],
 "tools":[{"type":"function","function":{"name":"browser",...}}],"tool_choice":"auto"}
```

响应（HTTP 200，正常结束）：

```json
{"choices":[{"index":0,"message":{"role":"assistant","content":
 "作为AI助手，我无法直接访问或查看任何网站的内容，包括百度首页。但是，我可以帮助您了解如何在百度中搜索相关信息。只需在百度搜索框中输入您想了解的主题，然后点击搜索按钮即可。..."},
 "finish_reason":"stop"}]}
```

**没有任何 `tool_calls` 字段。** 模型直接宣称"我无法访问网站"并给出 curl 命令行示例——
这正是没被训练过工具调用的 1.5B 模型的典型表现。

### 2. 流式也一样

```
data: {"choices":[{"delta":{"role":"assistant","content":""},...}]}
data: {"choices":[{"delta":{"content":"我是一个文字模型，无法直接访问互联网进行操作。但我可以帮助你了解如何查看百度首页的信息。以下是一个简单的命令行示例，使用了`curl`命令..."}}]}
```

依然纯文本，无 `tool_calls`。

### 3. 手机端稳定性

```
192.168.3.4 /health -> TimeoutError timed out      # 深度睡眠，TCP 连上但不回包
192.168.3.3 /health -> HTTP 502 Bad Gateway        # 不是这个 IP
```

`gateway.log` 里也能看到同样的模式：

```
08:56:21 POST /v1/chat/completions -> ERR 30486ms (attempt 1) [TimeoutError] timed out
08:56:53 POST /v1/chat/completions -> ERR 29547ms (attempt 2) [TimeoutError] timed out
08:57:26 POST /v1/chat/completions -> ERR 29138ms (attempt 3) [TimeoutError] timed out
09:17:35 手机地址已锁定 192.168.3.4
09:17:36 POST /v1/chat/completions -> 200 1073ms (attempt 1)   # 醒来后立刻成功
```

## 对架构的影响

原生 function calling 在这个模型上**走不通**——不是代码问题，是模型能力问题。

因此 `agent_tool_mode` 默认设为 `text`：直接走文本协议 `[[TOOL: name {json}]]`，
并注入 **few-shot 对话示例**（小模型靠示例学格式，光给规则说明学不会）。

### 代码层面的两个必要修正

1. **降级判据必须区分「上游拒绝」与「网络超时」**
   原实现把任何错误都当成"不支持 tools"→ 降级。这在手机休眠时会把超时误判成能力缺失，
   产生"上游不支持原生 tools"的假提示（界面上表现为：提示出现后就再无答复）。
   现改为：仅 HTTP 4xx 才降级，超时/5xx 直接报错。

2. **降级提示不能走致命错误通道**
   原实现里降级提示发的是 `("error", ...)`，前端 `__onError` 会清空气泡并置 `busy=false`，
   导致后续 token 全部丢失——**这正是截图里"只看到警告、没有答复"的直接原因**。
   现拆分为 `("notice", ...)`（非致命，显示为灰色提示条，不影响输出）与 `("error", ...)`（致命）。

## 待验证项

因手机当时深度睡眠，**few-shot 下 1.5B 模型能否稳定输出 `[[TOOL: ...]]` 尚未实测确认**。

复测方式（手机唤醒后执行）：

```sh
python probe_text_protocol.py
```

该脚本用与 agent 完全一致的 system 提示 + few-shot 示例，检验输出中是否含 `[[TOOL:`。

若仍不输出，说明该模型无法通过提示工程获得工具调用能力，需换模型（≥7B 且经 function calling
训练）或在手机端服务里补一层规则解析。
